# ERM Textbook Style Guide

**Package:** `erm_textbook_style.sty`  
**Location:** `second_ed/style/erm_textbook_style.sty`  
**Last updated:** June 2026 (updated through Chapter 8)

This guide covers everything needed to format a new chapter consistently with the rest of the book. Read it once before starting a new chapter; keep it open while writing the LaTeX.

---

## 1. Document Setup

Every chapter file starts the same way:

```latex
% !TeX root = Chapter_XX_Title.tex
\documentclass[11pt,openany]{book}
\usepackage{graphicx}
\usepackage{amsmath,amssymb}
\makeatletter
\def\input@path{{second_ed/style/}{../style/}}
\makeatother
\usepackage{erm_textbook_style}
\providecommand{\tightlist}{\setlength{\itemsep}{0pt}\setlength{\parskip}{0pt}}
\emergencystretch=2em
```

The `\input@path` lets the style package be found whether you compile from the repo root or from inside the chapter folder. Do not change the document class; `book` with `11pt` and `openany` is required so running heads and chapter numbering work correctly.

If the chapter has figures generated by R scripts, add a `\graphicspath` pointing to the relevant subfolder:

```latex
\graphicspath{{second_ed/rscripts/chapterN/}{../rscripts/chapterN/}}
```

## 3. Chapter-Opening Structure

Every chapter follows this opening sequence in order:

### 3.1 Chapter Title

```latex
\chapter{Title of the Chapter}
\label{chap:short-label}
```

The `\chapter` command produces the "Chapter N" prefix and the Iowa Gold rule automatically. Do not add it manually.

### 3.2 Learning Objectives

```latex
\begin{learningobjectives}
  \item Verb-first objective stating a specific skill.
  \item Second objective.
\end{learningobjectives}
```

- Yellow-gold background (`ERMBoxGold`), dark gold border.
- Each item should start with an action verb (Explain, Compare, Identify, Apply, Describe, Evaluate).
- Aim for 5–7 items. Fewer than 4 is thin; more than 8 suggests the chapter is trying to do too much.

### 3.3 Chapter Overview

```latex
\chapteroverview{%
  First paragraph of the overview.

  Second paragraph if needed.%
}
```

- Black border with white title bar on a cream background.
- 2–3 paragraphs. Says what the chapter covers and why it matters relative to adjacent chapters.
- Written last, after the chapter is complete.

### 3.4 Opening Corporate Example (if applicable)

```latex
\begin{corporateexample}[Company Name and the Event Title]
  Narrative text...
  \source{Citation for the case.}
\end{corporateexample}
```

- Blue background (`ERMBoxBlue`), dark gray border.
- Auto-numbered: "Corporate Example N.1: Title" (counter resets per chapter).
- Place immediately after `\chapteroverview`, before the first `\section`.
- End with `\source{...}` citing the primary source(s) for the case.
- Write as narrative prose. Do not use bullet lists inside case study boxes.
- **Multiple opening examples:** When a chapter uses two opening cases (see Chapter 4), place them sequentially after `\clearpage` and before the first `\section`. Both receive auto-numbers (e.g., Corporate Example 4.1 and 4.2). This is appropriate when two cases together motivate the chapter's central tension — do not use more than two opening cases.

## 4. Section Hierarchy

```latex
\section{Section Title}        % numbered, large bold black
\subsection{Subsection Title}  % numbered, bold dark gray
\subsubsection{Sub-sub title}  % numbered, bold dark gray (use sparingly)
```

Sections are numbered automatically by the `book` class. Do not add numbers manually. Use `\section*{...}` only for unnumbered end-matter sections (References, Key Terms, etc.) and always pair with `\addcontentsline{toc}{section}{Title}` so they appear in the table of contents.

**Inline sub-headings** within a subsection use `\textbf{Heading}` on its own line:

```latex
\textbf{The Friction: Something Specific}

Prose follows here...
```

This is preferable to a `\subsubsection` when the heading is a label or category rather than a structural section break.

## 5. Box Environments

All boxes use the shared `erm box` style: auto-numbered within the chapter, breakable across pages, consistent padding and arc. Each has a distinct color scheme signaling its purpose.

### 5.1 Summary of Available Boxes

| Environment | Background | Border | Title Prefix | Use for |
|-------------|-----------|--------|--------------|---------|
| `corporateexample` | Blue `ERMBoxBlue` | Dark gray | Corporate Example N | Real corporate case studies |
| `workedexample` | Gold `ERMBoxGold` | Dark gold | Worked Example N | Solved quantitative problems |
| `regulatorynote` | Gray `ERMBoxGray` | Mid gray | Regulatory Note N | Laws, regulations, frameworks, standards |
| `managerialinsight` | Cream `ERMBackground` | Black left rule | Managerial Insight N | Practitioner perspective, "in practice" notes |
| `commonpitfall` | Red `ERMBoxRed` | Dark gray | Common Pitfall N | Mistakes to avoid |
| `whythismatters` | Cream `ERMBackground` | Gold left rule | Why This Matters N | Motivating framing before a technical section |
| `boardroomquestion` | Gold `ERMBoxGold` | Black | Boardroom Question N | Questions a board or CRO should ask |
| `checklist` | Green `ERMBoxGreen` | Dark gray | Checklist (or custom title) | Step-by-step implementation checklists |

### 5.2 Usage Syntax

All numbered boxes take an optional title argument:

```latex
\begin{corporateexample}[Optional Title After the Colon]
  Content...
\end{corporateexample}

\begin{workedexample}[Optional Title]
  Content...
\end{workedexample}

\begin{regulatorynote}[Optional Title]
  Content...
\end{regulatorynote}
```

The `checklist` environment takes an optional title that replaces the default "Checklist":

```latex
\begin{checklist}[ERM Implementation Checklist]
  \item First item
  \item Second item
\end{checklist}
```

### 5.3 Box Placement Guidelines

- Place boxes in the flow of the text where they support the surrounding prose — not as afterthoughts dumped at the end of a section.
- Each box should earn its place. Ask: does this content interrupt the narrative badly as prose? If prose works fine, use prose.
- `corporateexample` boxes typically appear once per chapter, at the opening, but a second case study mid-chapter is fine if it genuinely illustrates a distinct point.
- `workedexample` boxes follow the theory they illustrate immediately.
- `regulatorynote` boxes work well for standards or legal frameworks that would slow the prose if embedded inline (see the COSO five-component summary in Chapter 2 as a model).
- Do not use more than one `commonpitfall` or `boardroomquestion` per chapter unless the chapter specifically focuses on implementation.

### 5.4 Source and Note Lines Inside Boxes

Use these two commands at the end of box content:

```latex
\source{Full citation for the source of the material.}
\figurenote{Methodological note or explanation.}
```

`\source` and `\figurenote` produce small italic gray lines beginning with *Source.* and *Note.* respectively. They work inside boxes and beneath figures.

## 6. End-of-Chapter Elements

End-of-chapter material appears in this order: Key Takeaways → Key Terms (if present) → Short-Answer Questions (if present) → Discussion Questions (if present) → Mini-Case (if present) → Further Reading (if present) → References.

### 6.1 Key Takeaways

```latex
\begin{keytakeaways}
\item
  \textbf{Bold Label}: One or two sentences describing the takeaway.
\item
  \textbf{Second Label}: Sentence.
\end{keytakeaways}
```

- Produces an unnumbered `\section*{Key Takeaways}` heading with TOC entry automatically.
- Each item has a bold label followed by a colon and the content.
- Aim for 5–8 items. Mirror the learning objectives: each objective should have a corresponding takeaway.

### 6.2 Key Terms

```latex
\begin{keyterms}
  \item[\keyterm{Enterprise risk management}] Definition in one or two sentences.
  \item[\keyterm{Risk appetite}] Definition.
\end{keyterms}
```

Use `\keyterm{term}` to bold the term. The environment produces a hanging-indent description list.

### 6.3 Discussion Questions

```latex
\begin{discussionquestions}
\item Question one?
\item Question two?
\end{discussionquestions}
```

### 6.4 Short-Answer Questions

```latex
\begin{shortanswerquestions}
\item Question that has a specific right answer.
\end{shortanswerquestions}
```

### 6.5 Mini-Case

```latex
\begin{minicase}{Company Name or Scenario Title}
  Narrative text for the case. 2–4 paragraphs.

  \begin{discussionquestions}
  \item Case-specific question.
  \end{discussionquestions}
\end{minicase}
```

### 6.6 Further Reading

```latex
\begin{furtherreading}
\item Froot, K.\,A., Scharfstein, D.\,S., \& Stein, J.\,C. (1993)...
\end{furtherreading}
```

### 6.7 References

```latex
\section*{References}
\addcontentsline{toc}{section}{References}
\begingroup
\sloppy

Author, A. (Year). \emph{Title}. Publisher.

\endgroup
```

- Use `\begingroup \sloppy ... \endgroup` to prevent overfull hboxes in URLs.
- Format: APA 7th edition.
- Journal titles and book titles in `\emph{}`.
- Use `\url{}` for URLs.

## 7. Figures and Tables

### 7.1 Figures

```latex
\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{filename.png}
  \caption{Caption text. Sentence describing what the figure shows.}
  \label{fig:short-label}
  \figurenote{Methodological note, e.g., indexing base or data source.}
\end{figure}
```

- All figures produced by R should use `theme_erm_textbook()` from `rscripts/erm_textbook_style.r`.
- Save figures as PNG at 300 dpi minimum, or as PDF for vector graphics.
- Reference every figure in the text before it appears: "Figure~\ref{fig:label} shows...".

### 7.2 Tables (using `ermtable`)

```latex
\begin{ermtable}{Caption text here}{tab:label}
  \begin{tabularx}{\linewidth}{lYY}
    \toprule
    Column 1 & Column 2 & Column 3 \\
    \midrule
    Row data & Data & Data \\
    \bottomrule
  \end{tabularx}
  \tablenote{Table source or methodological note.}
\end{ermtable}
```

Use `tabularx` with `Y` columns (defined as `\raggedright\arraybackslash X`) for text-heavy columns. Use standard `l`, `c`, `r` for short or numeric columns.

## 8. Mathematics

Inline math: `\( ... \)`  
Display math: `\[ ... \]` or `equation` environment for numbered equations.

```latex
% Inline
The expected return is \( E[R_i] = R_f + \beta_i (E[R_M] - R_f) \).

% Display, unnumbered
\[
\text{Cost of Risk} = \text{Expected Retained Losses} + \text{Risk Control Costs} + \ldots
\]

% Display, numbered
\begin{equation}
  \label{eq:cost-of-risk}
  C = L + K + F + I
\end{equation}
```

Reference numbered equations as Equation~\eqref{eq:label}.

## 9. Paragraph Length

Paragraphs must contain at least three sentences. One- and two-sentence paragraphs are prohibited in body text.

This is a textbook, not a trade book or a slide deck. Students read chapters sequentially and need developed argument, not fragments. A paragraph that ends after two sentences almost always means one of two things: the idea was not fully explained, or it belongs merged with the paragraph before or after it. Either way, the fix is to write more, not to let it stand.

The only exceptions are:

- The final sentence of a section when used deliberately as a one-line conclusion (use sparingly, no more than once per section).
- Items inside `keytakeaways`, `learningobjectives`, or other list environments, where each item is structurally a single point.
- Captions, source lines, and figure notes.

When reviewing a draft, flag every paragraph of fewer than three sentences and either expand it or absorb it into an adjacent paragraph.

## 10. Emphasis, Bold, and Key Terms

- `\emph{text}` — italics for emphasis, titles mentioned inline, or technical terms on first use.
- `\textbf{text}` — bold for inline sub-headings (e.g., "**The Friction:**") and key terms in takeaway items.
- `\keyterm{text}` — bold; use in the `keyterms` environment for defined terms.
- Do not underline. Do not use ALL CAPS for emphasis.

## 11. Lists

Lists use Iowa Dark Gold bullets automatically:

```latex
\begin{itemize}
  \item First item.
  \item Second item.
\end{itemize}

\begin{enumerate}
  \item First step.
  \item Second step.
\end{enumerate}
```

Use `\tightlist` inside boxes or when vertical spacing should be compressed:

```latex
\begin{itemize}
\tightlist
\item Compact item.
\end{itemize}
```

**When to use lists vs. prose:** Use a list when items are genuinely discrete and parallel. Three or fewer items usually read better as prose ("X, Y, and Z"). Do not convert every set of related points into a bullet list.

## 12. Cross-References

Always use `\label` and `\ref` / `\eqref` rather than hard-coded numbers.

```latex
% In the text:
as shown in Figure~\ref{fig:jnj-tylenol}
see Section~\ref{sec:erm-evolution}
Chapter~\ref{chap:why-risk-management-matters}
Equation~\eqref{eq:cost-of-risk}
```

Use `~` (non-breaking space) between the word and the `\ref` to prevent line breaks.

Labeling conventions:

| Type | Prefix | Example |
|------|--------|---------|
| Chapter | `chap:` | `\label{chap:enterprise-risk-management}` |
| Section | `sec:` | `\label{sec:erm-evolution}` |
| Subsection | `subsec:` | `\label{subsec:coso}` |
| Figure | `fig:` | `\label{fig:jnj-tylenol}` |
| Table | `tab:` | `\label{tab:coso-components}` |
| Equation | `eq:` | `\label{eq:cost-of-risk}` |

## 13. Footnotes

Use standard LaTeX footnotes for brief clarifying information that would interrupt the text:

```latex
Text in the chapter.\footnote{Explanatory note that does not fit inline.}
```

Keep footnotes short — one or two sentences. If a footnote is growing to a paragraph, it probably belongs in the text or should be cut. Do not use footnotes for citations; use the References section instead.

## 15. Compilation

Compile with `pdflatex` from the chapter folder (or repo root):

```powershell
pdflatex -interaction=nonstopmode Chapter_XX_Title.tex
pdflatex -interaction=nonstopmode Chapter_XX_Title.tex   # second pass for refs
```

Two passes are needed to resolve cross-references and TOC entries. If you are using `biber` for bibliography, the sequence is `pdflatex → biber → pdflatex → pdflatex`. Currently, references are typed manually so `biber` is not needed.

## 16. Displaying Code and Formulas

Chapters that include quantitative tool demonstrations (Excel formulas, R code, pseudocode) use two lightweight constructs defined in the chapter preamble. Do **not** add these to `erm_textbook_style.sty`; they live in the chapter file because only quantitative chapters need them.

### 16.1 Inline Formula

```latex
% Chapter preamble
\newcommand{\excelcode}[1]{{\small\ttfamily #1}}
```

Use `\excelcode{=AVERAGE(claim\_amounts)}` for a single Excel formula mentioned inline in a sentence. Escape underscores as `\_`.

### 16.2 Multi-Line Code Block (`excelblock`)

```latex
% Chapter preamble
\newenvironment{excelblock}%
  {\begin{quote}\small\ttfamily\setlength{\parskip}{2pt}}%
  {\end{quote}}
```

Use `excelblock` for two or more lines of formulas or pseudocode:

```latex
\begin{excelblock}
=AVERAGE(claim\_amounts)\\
=MEDIAN(claim\_amounts)
\end{excelblock}
```

- Produces a small-font monospace indented block with 2 pt between lines.
- Use `\\` to separate lines; leave a `\medskip` between logically separate groups.
- Precede the block with a bold label in the surrounding prose, e.g., `\textbf{Step~2: Build Severity Distribution.}` so the code is not free-floating.
- Comment lines inside the block use `\%` (escaped percent).
- Do **not** use `lstlisting`, `verbatim`, or any additional packages for this purpose — the two lightweight commands above are sufficient for the level of code complexity expected in this textbook.

### 16.3 When to Use Code Blocks

Use `excelblock` only when the formula is genuinely part of the learning objective (i.e., students are expected to replicate the calculation). Do not include Excel formulas for trivial arithmetic that students can perform without tool guidance. If a full Excel assignment is given, put the detailed formula guidance inside the `minicase` environment at the end of the chapter rather than in the body.

## 17. Chapter-Specific Notes

### Chapter 1 — Why Risk Management Matters
Opening case: Johnson & Johnson Tylenol recall (`corporateexample`). Establishes the core MM irrelevance-propositions framework. The Tylenol case makes the case for hedging under financial distress; the chapter is primarily theoretical with one applied box.

### Chapter 2 — Enterprise Risk Management: Evolution, Frameworks, and Institutional Context
Opening case: GM ignition switch crisis (`corporateexample`). The GM case is the motivating example for the entire ERM argument — siloed risk management versus enterprise-level integration. COSO framework summarized in a `regulatorynote` box. The key stylistic convention established in this chapter: use `---` separators between major sections, and keep the COSO box tight (it was a sequential list in the original and was deliberately condensed).

### Chapter 3 — Risk Identification: Categorizing and Discovering Enterprise Risks
Opening case: Netflix and the Red Envelope Problem (`corporateexample`). Two structural conventions introduced in this chapter that should carry forward:

**Enterprise-before-silo framing.** The chapter overview explicitly states that the goal of risk identification is not four separate lists managed by four functions, but a single integrated view. This framing should appear in or near the overview of any chapter that uses the four-quadrant taxonomy or its derivatives. Do not let taxonomy discussions drift into administrative silos.

**Definition + vivid example at quadrant openings.** Each risk quadrant section opens with a short, concrete example immediately after the conceptual definition, before moving to characteristics and management approaches. The pattern is: *definition paragraph → one-sentence illustrative example that a student can picture* → characteristics → tools. Examples used in Chapter 3:
- Hazard: a warehouse fire that stops shipments overnight
- Financial: a sudden euro appreciation that makes every imported component more expensive the moment the exchange rate moves
- Operational: a payment processing system crash during peak holiday traffic that prevents purchases for six hours
- Strategic: a retailer's dense physical store network, which was a competitive advantage in 1995 and a strategic risk a decade later

These should be treated as canonical anchors for the quadrant concepts across the book. If later chapters reference the four quadrants, the same examples (or equally specific ones) should be used for consistency.

**Business interruption classification.** Chapter 3 establishes definitively that business interruption is an operational/hazard risk, not a financial risk. This classification should not be contradicted in later chapters. If later material discusses business interruption insurance or supply chain finance, the quadrant classification must remain consistent with Chapter 3.

**10-K Risk Factors as a pedagogical tool.** Chapter 3 introduces the SEC Form 10-K Risk Factors section as an analytical resource. Later chapters that discuss specific risk types (credit risk, commodity risk, regulatory risk) should cross-reference this framework and, where appropriate, include excerpts or examples drawn from actual Risk Factors disclosures.

### Chapter 4 — Risk Quantification and Qualification

**Opening cases:** Two `corporateexample` boxes are used (Corporate Example 4.1: LTCM; Corporate Example 4.2: Moneyball). Both serve as the foundational motivating cases for the chapter's central argument about the power and limits of risk quantification. They are referenced repeatedly in the body: LTCM in the skewness section (fat tails), the VaR limitations section, and the qualitative-assessment section; Moneyball in the non-financials subsection and the conclusion of Section 8. This cross-referencing pattern — introduce a case at the opening, return to it as specific technical points are made — should be followed in subsequent chapters that use opening cases.

**Two-case opening convention.** The dual opening example is appropriate when one case illustrates *what goes wrong with quantification* (LTCM: overconfidence in models) and the other illustrates *what goes right* (Moneyball: disciplined measurement creating competitive advantage). Do not use two opening cases unless there is a genuine conceptual tension that requires both.

**Statistical and mathematical content.** Chapter 4 is the first chapter with substantial mathematics. Conventions established here:
- Inline math: `\( ... \)` — used for probabilities, rates, and simple expressions embedded in prose.
- Display math (unnumbered): `\[ ... \]` — used for the key equations (Expected Loss formula, variance formula, standard deviation aggregate formula). Display math is used when the equation is a learning objective, not for simple arithmetic.
- Numbered equations: `\begin{equation}...\end{equation}` — reserved for equations that will be cross-referenced later. Chapter 4 does not use numbered equations; if subsequent chapters develop the same framework further, they should number equations that carry forward.
- Aligned multi-line calculations: `\begin{align*}...\end{align*}` — used in case study sections when a multi-step calculation is shown. The alignment point is the `=` sign.

**Case study structure.** Chapters that walk through quantitative case studies in the body text (not in boxes) use `\textbf{Step~N: Title.}` as inline headings for numbered analytical steps. This is distinct from `\subsubsection{}` (which generates a numbered heading and TOC entry). Use the inline bold heading when the steps are sub-procedural within an existing `\subsection{}`.

**Code and formula display.** Chapter 4 introduces the `\excelcode{}` and `excelblock` constructs described in Section 16. Define them in the chapter preamble, not in the style package. Any subsequent chapter with similar Excel or R formula demonstrations should copy these definitions from the Chapter 4 preamble.

**Tables with data.** Chapter 4 introduces `ermtable` for empirical data tables (the Northland Manufacturing annual experience table). Use `tabularx` with `Y` columns for text-heavy columns; use `c` for year/count columns and right-align (`r`) for dollar amounts. Dollar signs in table cells: use `\$` not `$`.

**End-of-chapter structure for quantitative chapters.** Chapter 4 uses `shortanswerquestions` (calculation-based) and `discussionquestions` (conceptual/analysis) separately. The Excel assignment uses `minicase`. This three-part end-matter (short answer + discussion + mini-case) is the appropriate template for quantitative chapters. Theory-heavy chapters (Chapters 1–3) typically use only `discussionquestions`.

**Non-financial quantification.** Section~4.1.3 (Quantification Beyond Finance) establishes that frequency-severity analysis applies to hospitals, airlines, sports analytics, and any domain with repeated, partially predictable adverse events. Later chapters that use quantitative methods outside a financial-institution context should cross-reference this section rather than re-arguing the general case.

### Chapter 5 — Risk Appetite and the ERM Process

**Opening case:** adidas aggregate exposure case (`corporateexample`). A single opening case, consistent with the convention in Chapters 1–3. The adidas case is chosen because it illustrates a *mature* ERM program where appetite genuinely drives the process — providing a contrast to the chapter's central argument that most firms must build identification and quantification capacity before appetite can be made operational.

**ERM cycle sequencing argument.** The chapter overview and Section~5.3.1 explicitly address the "chicken-and-egg" problem: in theory, appetite precedes identification and quantification; in practice, most firms do the reverse early in their ERM development. This is a substantive conceptual point, not throat-clearing. Future chapters that revisit the ERM cycle should not contradict this framing; if a later chapter discusses "setting appetite as the first step," it should acknowledge this is the mature-program ideal.

**Hierarchy diagram using `managerialinsight`.** Section~5.2.5 uses a `managerialinsight` box containing a `tabular` display to show the four-level hierarchy: Capacity → Appetite → Tolerance → Limits. This is the appropriate pattern for any framework or taxonomy diagram that is too compact to justify a full figure and too important to leave as a bullet list. Use `tabular` with arrows (`$\downarrow$`) and `\color{ERMMidGray}` for the explanatory annotations.

**No `shortanswerquestions` or Excel/code blocks.** Chapter 5 is conceptual rather than quantitative. The end-of-chapter material uses only `discussionquestions` and a `minicase` (applied assignment). This matches the Chapters 1–3 pattern. Do not add `shortanswerquestions` to non-quantitative chapters.

**Mini-cases within the chapter body.** Section~5.7 presents three brief company cases (InnovateTech, Midwest P\&C, PowerGrid) as regular subsections using `\subsection{}`, not `corporateexample` boxes. This is appropriate when there are three or more parallel illustrative cases of similar length — using boxes for all three would visually dominate the chapter. Instead, a short transitional sentence at the start of the section explains the pedagogical purpose. Use the same pattern in other chapters with three or more parallel cases.

**`minicase` as applied assignment.** The end-of-chapter applied assignment uses `minicase{Title}`. When an assignment is structured as a multi-part project (Parts 1, 2, 3) rather than a set of short questions, use numbered `enumerate` inside `minicase` for the parts. Include explicit submission requirements and evaluation criteria as bold inline headings within the environment.

**Pitfalls section as inline bold paragraphs.** Section~5.9 covers six distinct failure modes as inline bold headings + prose paragraphs rather than a bulleted list or individual `commonpitfall` boxes. This pattern is appropriate when each pitfall has enough discussion (3–5 sentences) to warrant prose treatment. Individual `commonpitfall` boxes are better suited to 1–2 sentence callouts scattered through a chapter; collecting many pitfalls into a dedicated section works better as prose paragraphs.

### Chapter 6 — Examining the Firm's Risk Portfolio

**Opening case:** Maersk/NotPetya (`corporateexample`). The case is the chapter's running example of *correlated* losses — the opposite pole from diversification. It is referenced repeatedly in the body (aggregate exposure in 6.1, latent dependencies in the register pitfalls, tail dependence in 6.5.5, the cyber stress scenario in 6.9.3, organizational change in 6.11.3). This follows the Chapter 4 convention: introduce the case at the opening, return to it as specific technical points are made.

**Cross-chapter case callbacks.** Chapter 6 deliberately calls back to the adidas case from Chapter 5 (stochastic simulation of the aggregate portfolio against appetite and capacity thresholds) when discussing appetite compliance and Monte Carlo aggregation. When a prior chapter's opening case directly illustrates a current chapter's machinery, reference it by name rather than inventing a new example.

**Worked-example numbers must be reproducible.** All aggregation examples in Chapter 6 (the bank economic-capital example, the five-risk variance-covariance example, the four-risk diversification example, and the GMC case) were verified by direct computation from the stated inputs. Any chapter presenting numerical examples that students can recompute from given inputs (SDs plus a correlation matrix) must have internally consistent numbers — compute them, do not estimate them. The GMC Monte Carlo results are generated by `rscripts/chapter6/c6_aggregate_loss.r`, so the figure, the case text, and the simulation agree.

**Correlation matrices as `ermtable`.** Correlation matrices use `ermtable` with plain `tabular`, `c` columns, bold row/column headers, and 1.00 on the diagonal. Register-style tables with a free-text notes column use `tabularx` with a trailing `Y` column.

**Figure from simulation.** Figure 6.1 (aggregate loss distribution) is produced by the chapter R script using `theme_erm_textbook()`, with VaR thresholds annotated using gold label boxes (the same annotation style as the Chapter 1 J&J figure). Figures that display simulation output should carry a `\figurenote` stating the method, the number of trials, and any display trimming.

**End-of-chapter structure.** Chapter 6 keeps the original course-assignment structure: 12 tagged discussion questions (each prefixed with a bold tag — `\textbf{Conceptual:}`, `\textbf{Calculation:}`, etc.), a graded multi-part exercise with point values inside `minicase` (TechRetail), and a separate unnumbered `\section*{Advanced Challenge: ...}` (with `\addcontentsline`) for the optional programming extension. Use the bold question tags in any chapter whose question set mixes conceptual, calculation, and application items. The unnumbered Advanced Challenge section is the pattern for optional material that should not be part of the graded mini-case.

### Chapter 7 — Loss Control and Risk Reduction

**Opening case:** Crestline Mutual / Collins family electrical-fire prevention (`corporateexample`). The case is the chapter's running example because it illustrates *both* halves of the frequency-severity framework in one narrative (fewer fires; smaller fires when they occur), plus control-group measurement and insurer-side loss control economics. It is called back in the frequency section (3.1), severity section (4.1), engineering controls (5.2), leading/lagging indicators (6.3), benchmarking (9.3), the deductible discussion (10.2), the Riverside case (11.3), and the appendix's deferral-option discussion. Same pattern as Chapters 4 and 6: introduce at the opening, return at specific technical points.

**Cross-chapter case discipline.** Case-study companies must not collide across chapters. The original Chapter 7 draft reused "Precision Parts" from Chapter 4 with inconsistent headcounts and falsely claimed continuity with Chapter 4's workers' compensation VaR case (which is Northland Manufacturing). Fix applied: Chapter 7's firms are now **Mercer Tool & Stamping** (machine guarding, Section 8.1) and **Riverside Metal Products** (WC case study, Section 11), and Section 11 references Chapter 4's VaR *methodology* (Northland) without claiming the same company. When drafting a new chapter, grep prior chapters for any company name you reuse.

**Retention/deductible arithmetic.** Section 10.2 establishes the correct way to present deductible-layer examples: specify the claim-size distribution (how many claims fall below the old deductible, between the deductibles, and above the new deductible) and compute retention per layer. A claim adds retained cost only up to min(settlement, deductible). Never apply the full deductible-difference to claims that settle inside the layer, and check that retained losses never exceed ground-up losses. The three-strategy comparison is shown in an `ermtable`.

**Footnotes instead of a "Footnotes" section.** The old draft collected five numbered footnotes in an end-of-chapter section. The .tex attaches them as real `\footnote{}` calls at the relevant points (TCOR definition, OSHA recordkeeping, EMR rating bureaus, Heinrich triangle, OSHA VPP). Markdown drafts may keep a Footnotes section; the LaTeX should not.

**Chapter appendix pattern (new).** Chapter 7 introduces a chapter-level appendix placed *after* all end-of-chapter material (after References). Conventions:

- Heading: `\section*{Appendix 7A: Title}` with `\addcontentsline`.
- Internal sections are numbered `7A.1, 7A.2, …` by resetting the section counter and renumbering:

```latex
\clearpage
\setcounter{section}{0}
\renewcommand{\thesection}{7A.\arabic{section}}
\renewcommand{\thesubsection}{\thesection.\arabic{subsection}}
\renewcommand{\theHsection}{appendix7A.\arabic{section}}
\renewcommand{\theHsubsection}{\theHsection.\arabic{subsection}}
```

  The `\theHsection` redefinitions are required — without them hyperref emits "destination with the same identifier" warnings because the reset counter collides with the body sections.
- The appendix has its own `\section*{Appendix References}` listing only sources cited in the appendix; do not merge them into the chapter references.
- Appendix content style: working-paper framing (abstract, keywords, future-research sections) is stripped; the appendix reads as textbook material addressed to students who know introductory corporate finance.
- The appendix's numbered equations use the standard `equation` environment and may be cross-referenced from the body.

**Appendix-body numerical consistency.** The appendix's complete numerical example (7A.9) reanalyzes the Section 8.1 Mercer case and must use identical inputs (I₀ = $125,000, C = $8,000, ΔL = $183,920, EMR 1.24 → 0.89, $67,000 premium savings). When an appendix extends a body case, recompute everything from the body's inputs — the original draft mixed two companies' data and double-counted indirect costs (the body case's severity was already on a total-cost basis). The double-counting warning is now itself a teaching point in 7A.6.1 and 7A.9 Step 4.

**Greek letters from RTF/Word sources.** Symbol-font Greek letters in converted RTF arrive as mojibake (`ë` for λ, `Ä` for Δ, `ô` for τ, `Ó` for Σ, `ñ` for ρ, `â` for β). Always re-set such material as proper LaTeX math.

### Chapter 8 — Risk Finance and Alternative Risk Transfer

**Opening case:** Oriental Land Company / Midori catastrophe bond (`corporateexample`). The case runs through the chapter the same way Maersk runs through Chapter 6: financing vs. control distinction (8.1), contingent-capital value channel (8.1.3), the ART rationale (8.7.1), SPV/collateral mechanics (8.8.2 — Midori is named as the worked illustration of the SPV role), parametric triggers and basis risk (8.8.3 — including the explicit caution that the 2011 outcome validated but did not eliminate basis risk), settlement speed (8.8.5), and the REIT case's basis-risk decision (8.10.3). Non-ASCII case text: use `\textyen` for ¥ and `T\=ohoku` for the macron.

**Sponsor cost of a cat bond is the spread, not the coupon.** Because the collateral trust earns the money market rate (SOFR), the sponsor's annual economic cost is principal × risk spread. The original draft divided an annual coupon cost by the bond term — a category error worth flagging because it surfaces in real TCOR analyses. All cat bond examples now price off SOFR; LIBOR references were retired.

**Reproducible decision tables.** The Brennan Industrial decision table (8.9.4) follows the Chapter 6/7 rule: every row recomputable from stated assumptions (premium = 1.35 × expected transferred losses; capital = 175% of expected retained losses at 10%). The pedagogical structure — unconstrained optimum vs. appetite-constrained optimum, with the "cost of the constraint" computed explicitly — is the template for retention optimization examples. Wide numeric tables may use `\small` plus `\setlength{\tabcolsep}{4pt}` inside `ermtable` when 8 columns are needed.

**Case-study arithmetic conventions (8.10).** All three case studies (GlobalTech, MidState, Coastal REIT) tie out exactly: component sums equal stated totals, savings percentages recompute, and the MidState pooling SD uses the Chapter 6 aggregation formula with the stated ρ = 0.45 (σ_pool = 7.83 × √(6 + 2·15·0.45) ≈ 35). When a case asserts a portfolio SD, state the correlation that produces it.

**Figure from schematic R script.** Figure 8.1 (risk financing spectrum) replaces the old draft's ASCII art with an R figure (`rscripts/chapter8/c8_financing_spectrum.r`) using `theme_erm_textbook()`. Schematic figures (illustrative index values, not data) must say so in the `\figurenote`. The R scripts source the shared theme via `source("second_ed/rscripts/erm_textbook_style.r")` and are run from the parent of `second_ed`.

**Company naming.** Generic "ABC" firms were renamed to avoid both blandness and collisions: Calloway Industries (finite risk), Lakeshore Power & Light (double trigger), Meridian Industrial Group (integrated program — *not* "Global Manufacturing Corp," which would collide with Chapter 6's GMC), Brennan Industrial Products (decision table), Cedar River Logistics (mini-case). Grep prior chapters before naming.

**Condensed mini-case pattern.** The original 15–20-page design project was condensed into a self-contained `minicase` (Cedar River Logistics) with complete data (per-line expected losses, SDs, premiums, correlation matrix, appetite limit, pricing assumptions), three graded tasks (50 points), and a normal-approximation instruction so the VaR computation is tractable. Full-retention VaR ($12.6M) deliberately violates the $9M appetite so students must design a partial-retention program. Use this pattern when an inherited assignment is too large for end-of-chapter material.

**Tax/regulatory currency.** The § 831(b) premium limit is stated with its year ("$2.85 million for 2025, indexed"); Notice 2016-66 is described together with its judicial invalidation and the 2024 final regulations. When citing indexed limits or contested guidance, anchor the figure to a year rather than asserting it timelessly.

## 18. Quick-Reference Checklist for a New Chapter

Before submitting or sharing a chapter draft, verify:

- [ ] Document class is `\documentclass[11pt,openany]{book}`
